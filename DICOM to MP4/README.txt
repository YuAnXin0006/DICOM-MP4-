DICOM 原始影像转 MP4 离线便携工具包 v1.0

使用：
1. 将 ZIP 完整解压到可写位置，例如 D:\DICOM转MP4工具包。不要在压缩软件内部运行。
2. 将医院提供的资料复制到“原始文件”中，可以保留整套子目录和 DICOMDIR。
3. 双击“开始转换.cmd”。不需要安装 Python、FFmpeg，也不需要联网或输入命令。
4. 查看“视频输出”；查看“转换记录”中的中文 CSV 和详细 JSONL 日志。
5. 结束窗口会显示成功、跳过、失败数量。存在失败时其他文件仍继续处理。

重要边界：
MP4 是便于观看的有损、8位派生副本，不与原始 DICOM 完全等价。
它不能替代 DICOM 归档、专业影像查看器或诊断依据。工具不作医学诊断。
原始文件不会被修改、重命名或覆盖。请保留完整原始资料。
不使用 AI，不插帧，不借用其他序列，不制造缺失的血管画面，不补造空白视频。
单帧对象仅延长显示为3秒静态MP4，清单明确标注，不称为动态录像。

文件和名称：
按内容而非扩展名识别 DICOM；支持无扩展名及数字命名。
递归处理，一个影像对象对应一个MP4，不把多份对象自动拼成一个序列。
保留相对目录；.dcm/.dicom/.ima 去除扩展名后加 .mp4，其他名称完整保留后加 .mp4。
同一目录的多个源文件若映射为同名输出，会统一附加稳定的12位文件名哈希，清单记录对应关系。
已有输出直接跳过，不覆盖，也不重新验证已有文件；跳过不表示旧视频已经校验合格。
要重新转换，先把对应的已有视频移到其他位置。
中文、空格及可写盘符路径使用相对定位；实际U盘设备未实测。
建议解压在较短路径，避免老旧Windows组件的长路径限制。只读U盘、空间不足会报错。

显示处理：
使用 pydicom 及成熟像素解码库，绝不自行解码医学压缩码流。
支持 MONOCHROME1/2、RGB、YBR_FULL、YBR_FULL_422、YBR_RCT、YBR_ICT 和标准调色板。
按有/无符号像素、BitsStored、Modality LUT / Rescale、VOI LUT /窗宽窗位处理。
有多组窗或LUT时采用第一组；支持共享及逐帧功能组中的缩放与VOI。
没有VOI时，采用整个对象统一的最小/最大显示范围，排除已声明的padding，记录范围。
MONOCHROME1反相；MONOCHROME2声明INVERSE时按声明反相。
不合成覆盖层、不应用遮片；不处理ICC显示器色彩管理、私有厂商显示算法或复杂呈现状态。
自定义 Presentation LUT、浮点像素、非标准色彩等不支持时明确失败。
保持像素矩阵，不拉伸、不裁切；奇数宽高仅在右侧/底部补黑边至偶数，并记录。
MP4使用方形像素；原始声明非方形像素时会告警，未为物理像素比例拉伸矩阵。
编码：H.264/libx264、CRF18、yuv420p、MP4、无音轨，无原始身份元数据写入。
原像素内已有的烧录姓名/标注会保留；文件路径和文件名也可能包含身份信息。

播放速度：
优先使用有效 FrameTimeVector，或逐帧 FrameAcquisitionDateTime；保留逐帧时间差。
最后一帧没有下一帧的时间依据，沿用前一间隔，并记录该假设。
其次使用 FrameTime、RecommendedDisplayFrameRate、CineRate；来源写入CSV。
显示/电影帧率不冒称为逐帧实测采集速度。
无可靠依据时明确采用默认15fps；不是原始帧率。单帧按25fps延长为3秒静态视频。
可变帧率不额外复制末帧；使用微秒时间基，并核对每一帧时间戳（2ms容差）。
支持间隔1ms至3600秒；超出范围报错，不擅自改速。

校验和异常：
每个新MP4先写临时目录，完成后执行FFprobe帧数/尺寸/编码/音轨/时长/逐帧时间戳核对，
再用FFmpeg严格完整解码（-xerror、-err_detect explode）。全部通过才成为正式输出。
时长容差为10ms或0.1%中的较大值。校验失败不发布为成功视频。
全零文件、空文件、损坏DICOM、不支持的传输语法/解码器分别记录。
无像素DICOM、DICOMDIR、显示设置和无关文件会跳过。
声明帧数或像素长度不符、坏压缩帧等会失败，不删帧、不补齐、不宣称修复。
合法DICOM中全零像素帧原样保留并提示复核；黑色像素本身不作为损坏证据。
库产生告警时在清单提示可能存在非标准元信息/可疑帧，未宣称修复。
工具无法发现所有临床意义上的缺失、医院未提供的文件、或仍可解码的错误像素。
普通日志不导出患者姓名等DICOM身份字段；库告警的字段原值不展开。
详细日志是逐文件的JSONL，可用记事本打开；CSV采用UTF-8 BOM，适合中文Excel。
路径和错误信息用于定位故障；请按医疗资料要求保管日志和派生视频。

空间和运行：
转换过程完全本地，不上传、不带遥测、不调用在线服务。不要同时启动多个转换窗口。
输入由pydicom读取；大对象需要足够内存。逐帧时间不同的对象会临时写RGB PPM，
临时空间约为 宽×高×3×帧数 字节，另加视频及原始数据。正常结束会清理临时文件。
异常断电可能残留“视频输出”下的.dicom_work_*目录；确认转换已退出后可删除残留临时目录。

系统和实测范围：
目标：64位Windows 10/11，普通x64处理器。内置Python3.12.10及依赖，含所需VC运行库。
实际运行验证：Windows 11 build 22621，64位；未在独立Windows10机器或全新虚拟机实测。
实际通过内置Python隔离模式运行：PATH只保留System32，PYTHONHOME/PYTHONPATH设为无效路径，
并通过真实的“开始转换.cmd”入口执行；sys.path全部指向包内。
这是脱离全局Python依赖的运行验证，不等于全部Windows硬件/系统版本兼容性保证。
实体U盘、网络盘、超长路径、厂商私有变体和所有真实医院设备均未穷尽测试。
详细支持UID及实际测试证据见“支持范围与验证报告.txt”和“构建与验证”。
